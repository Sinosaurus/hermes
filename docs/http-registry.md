# HTTP 私服接入与真实验收

HTTP 支持用于迁移现有私服，不等于传输安全。**推荐为私服配置 HTTPS；不能在明文 HTTP 上传密码、token 或认证头。** 本工具不调整服务器、网络或证书设置。

## 显式选择端点

默认仍拒绝非回环 HTTP registry。每次命令用 `--allow-http-registry` 明确指定允许的完整 registry 地址，可重复指定读写端点：

```sh
nova-hm plan --bundle ./bundle \
  --registry http://62.234.19.31:4873/ \
  --allow-http-registry http://62.234.19.31:4873/

nova-hm import --bundle ./bundle --run ./runs/http-check \
  --registry http://62.234.19.31:4873/ \
  --allow-http-registry http://62.234.19.31:4873/
```

`collect`、`recover`、`plan`、`import`、`promote`、`rollback` 使用同一授权规则。续跑及读取已保存 run 时仍需重新提供开关；不能由 bundle 或 run 文件自行授权网络端点。其他地址、协议、端口和路径不自动获准。显式资源清单的远程下载保持原 HTTPS 策略。

HTTP 模式使用隔离的匿名 npm 配置，不继承用户认证配置；项目目录中的 `.npmrc` 会阻止该模式，避免项目级配置绕过隔离。请在不含 `.npmrc` 的独立工作目录运行，并显式传入 registry、bundle、run。匿名 HTTP 发布还拒绝含 `publishConfig` 的制品，防止包内配置重新引入认证或更改端点；不会改写第三方包来绕过检查。npm 自身的下载重定向机制仍存在，精确端点授权不是完整网络沙箱，网络出口应由部署环境另行限制。这个模式不用于认证发布：遇到 `ENEEDAUTH`、401 或 403 时停下，改用有证书校验的 HTTPS 端点后走正常认证流程，不要写入虚假 token 或关闭 SSL 校验。

## 是否需要静态服务器

- 纯 npm 包及其 registry 依赖：npm 私服负责元数据和 tarball，不另需静态服务器。
- Electron、Playwright 浏览器及厂商安装器等额外文件：可能需要内网静态地址，也可能按厂商规定预置本地缓存。需按实际包及版本决定，不能只看 npm 安装成功。
- `export-resources` 导出暂存目录和 `resource-map.json`，不会上传或部署服务。可以复用现有 Nginx/对象存储，不必新增机器。

## 验收边界

真实验收分开记录：网络可达、元数据查询、tarball 下载、冻结批次校验、导入预检、写入及回读、空缓存安装、业务运行、tag 提升/回滚。前一项成功不能代表后一项成功。

HTTP 内容即使有哈希校验，也不能保证未受中间人篡改：可信摘要需通过独立可信渠道确认。工具验证的是已冻结批次的内容一致性，不代替供应商信任、漏洞审查或目标平台运行验收。

本工具按明确包规格、项目 npm 锁或已有安装树收集；并非全 npm 历史镜像，也没有按发布时间扫描整个 registry 的增量爬取器。此前全量历史同步讨论不能作为当前已实现能力。

## 2026-11-18 复核与认证验收入口

复核 PR #2 的提交 `5addfcb`：仍为草稿、未合并；本次没有向真实私服写入包或 tag，也没有发送凭据。匿名 HTTP `/-/ping` 仍返回 200。对相同 IP 和端口尝试 HTTPS 时，证书校验报告名称与 IP 不匹配，因此连接未通过；没有使用 `-k` 或关闭证书校验。此结果不能证明服务器已有可用的 HTTPS registry。

继续认证验收有两种路径：

1. **已有可信 HTTPS 地址**：提供 registry 的正式 HTTPS URL；使用受控环境中已有的认证。不要把 token 发到聊天。证书、自签 CA 信任和 URL 主机名必须匹配，不使用 `strict-ssl=false`。
2. **在有 SSH 权限的电脑上建立本地隧道**：由管理员确认服务器 SSH 用户、主机指纹及 registry 的服务器侧回环监听地址后，执行下列模板（`SSH_USER` 为占位符，不是实际账号）：

   ```sh
   ssh -N -o ExitOnForwardFailure=yes \
     -L 127.0.0.1:14873:127.0.0.1:4873 SSH_USER@62.234.19.31
   ```

   隧道只监听本机回环地址。另开终端确认 `http://127.0.0.1:14873/-/ping`，再使用 registry 的受支持登录方式认证；不要把已有公网 HTTP 地址上的认证配置复制过来。Hermes 命令使用 `--registry http://127.0.0.1:14873/`，**不加** `--allow-http-registry`，后者会主动启用匿名隔离。该模板未经服务器实际验证，不应假定服务器已经开放 SSH 或该端口回环可达。

无论选择哪条路径，先检查元数据中的 `dist.tarball` 与跳转目标，确保下载和回读不会逃回公网明文地址；如果私服仍广告原 HTTP IP 地址，应停下让管理员修正对外 URL，而不是扩大允许列表或绕过校验。

验收使用独立随机包名，按 `verify → plan → import → 精确版本/摘要回读 → 新目录和空缓存安装 → 夹具运行 → acceptance → promote → rollback` 执行并记录。`acceptance` 必须基于实际结果、与 bundle 摘要及读写端点一致，不能预填通过。`rollback` 只恢复 tag，不删除已经发布的版本。更换端点必须使用新的 run 目录，不能伪装旧 run 的目标地址。

**本次状态仍为等待安全认证通道，不能以公网 HTTP ping 成功或本地测试代替真实发布验收。** 纯 npm 包仍无需另建静态服务器；只有额外二进制/安装器资源才需按实际包评估现有静态服务或本地缓存。

本次工程复测环境为 Linux x64 / Node 24.22.3：默认 npm 11.9.0 因打包版本门槛导致 4 项集成测试失败；安装隔离的 npm 11.19.0 后，`npm run check` 全通过（10 文件、87 项测试，以及类型、lint、格式、构建、文档）。未改锁文件或放宽版本门槛。本地临时 registry 测试不代表用户私服认证验收通过。
